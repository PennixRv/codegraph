# 执行计划

1. 以同一四 owner 方案的明确批准执行原生 seal／approve／start；inline 主会话实施和检查，不派发子节点。
2. 修改尾注与必要原生协议说明，复用既有测试验证完整区段、缺失、陈旧和强制全文边界；不改算法。
3. 运行领域回归、完整 npm test、build 和既有 fork 发布必需门禁；完整差异审查与 spec 判断后提交、推送。
4. 核对未占用版本，按既有 CI 正式发行；根核验实际包、来源、摘要和目标内容后原生安装并验证真实驻留 MCP。
5. 原生归档／journal、必要推送；实时 origin/main 与最终 HEAD 对齐，再由根固定 gitlink。旧无关任务保持原状。

动态命令、失败及结果写入 execution-log.md；不修改封口文档。新增算法或范围必须回根重规划，不能顺带纳入。
